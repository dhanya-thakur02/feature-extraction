NLP Feature Extraction — Deep Dive

How raw text is transformed into numbers that machine learning models can actually learn from — from simple word counts to dense semantic vectors.

Why Feature Extraction?

The fundamental problem: machines only understand numbers

A model cannot learn from the string "the cat sat on the mat". It needs numbers. Feature extraction is the translation layer — it encodes words, sentences, or documents into fixed-length numeric vectors that capture meaning, frequency, or structure.

The choice of representation is one of the most consequential decisions in any NLP system. A poor representation throws away useful signal before the model even begins. A rich one makes even simple classifiers perform well.

Classification

⚡ Real-world example

Gmail labels your email as Spam or Not Spam the moment it arrives — that's a text classifier running on feature vectors built from the email body.

Spam detection, sentiment analysis, and topic labelling all start with feature vectors. BoW + logistic regression is still a strong baseline.

Search & Retrieval

⚡ Real-world example

When you search "best running shoes" on Google, TF-IDF ranks pages by keyword relevance. When you search Spotify or Netflix by mood, embeddings match your query by meaning, not exact words.

TF-IDF powers document ranking in search engines. Embeddings power semantic search — finding documents by meaning, not just keywords.

Neural Networks

⚡ Real-world example

ChatGPT, BERT, and Google Translate all begin by converting each word into a dense embedding vector. Without this step, the neural network would have no numeric input to process.

Deep learning models need continuous, dense input. Word embeddings (Word2Vec, GloVe, BERT) provide the compressed semantic layer neural nets need.

Step 0 — Building the Vocabulary
0

Vocabulary Construction

Every unique token across the corpus gets an index

Before any vector is created, every unique word across all documents in the corpus is collected into a vocabulary V. Each word maps to a fixed integer index. This index is what all downstream representations refer to.

Vocabulary size matters enormously. A tiny corpus might have V=50; a full web-crawl corpus used to train BERT has V=30,000+ (subword tokens). Larger vocabulary = higher-dimensional vectors = more memory and compute.

Hover over a word to see its index. Colour intensity = document frequency (how many docs contain this word).

👆 Hover a word chip to see its vocabulary index and document frequency.

⚠️ Vocabulary challenges

  • Out-of-vocabulary (OOV) words at inference time
  • Vocabulary explosion with n-grams
  • Morphological variants ("run","runs","running") treated as different words
  • Sparse vectors when V is large

✅ Mitigation strategies

  • Minimum frequency threshold (prune rare words)
  • <UNK> token for unseen words
  • Stemming / lemmatization before building vocab
  • Subword tokenization (BPE) for open-vocabulary coverage
Method 1 — Bag of Words (BoW)
1

Bag of Words

Count how often each vocabulary word appears — ignore all order

The Bag of Words model represents each document as a vector of word counts. The "bag" metaphor is intentional — you tip all the words into a bag, shake it, and count. Word order, grammar, and sentence structure are completely discarded.

Despite its simplicity, BoW is surprisingly effective. A BoW vector + logistic regression classifier can achieve strong baselines on spam detection, topic classification, and sentiment analysis — often 85–90% accuracy on clean datasets.

Select a document to see its BoW vector. Words with count > 0 are highlighted.

# BoW with scikit-learn from sklearn.feature_extraction.text import CountVectorizer corpus = ["the cat sat on the mat", "the dog sat on the log"] vec = CountVectorizer() X = vec.fit_transform(corpus) print(vec.get_feature_names_out()) # ['cat','dog','log','mat','on','sat','the'] print(X.toarray()) # [[1,0,0,1,1,1,2], [0,1,1,0,1,1,2]]
Method 2 — N-grams
2

N-grams

Sequences of N consecutive words become single features — preserving local order

N-grams extend BoW by treating sequences of N consecutive words as a single feature. A unigram (N=1) is a single word; a bigram (N=2) is a pair; a trigram (N=3) is a triple. This restores some local word-order information that BoW throws away.

Why this matters: "not good" and "good" are identical in BoW. As bigrams they're separate features — "not_good" vs "good" — and carry opposite sentiment signals. However, the vocabulary explodes: V unigrams become roughly V² bigrams and V³ trigrams, most of them sparse and useless.

Click a document to extract and visualise its unigrams, bigrams, and trigrams.

When bigrams help

  • "not bad" → negative overridden to positive
  • "New York" → one entity, not two separate words
  • "ice cream" → compound noun with specific meaning
  • "machine learning" → technical compound term

N-gram tradeoffs

  • Vocabulary grows exponentially with N
  • Data sparsity — most n-grams appear only once
  • Memory and compute scale badly for N≥4
  • N=1 or N=2 covers 95% of practical use cases
# N-grams with scikit-learn (unigrams + bigrams) from sklearn.feature_extraction.text import CountVectorizer vec = CountVectorizer(ngram_range=(1, 2)) # includes both X = vec.fit_transform(corpus) # Features: ['bad', 'good', 'not', 'not bad', 'not good', ...]
Method 3 — TF-IDF
3

TF-IDF (Term Frequency — Inverse Document Frequency)

Penalise common words, reward words that are unique to specific documents

BoW counts are biased toward frequent words like "the", "is", "and" — which are common everywhere and carry no discriminating signal. TF-IDF fixes this by scaling each word's count by how rare it is across the full corpus.

TF — Term Frequency

How often a word appears in this document (normalised by document length).

TF(t,d) = count(t,d) / |d|

IDF — Inverse Document Frequency

How rare this word is across the entire corpus. Rarer = higher IDF = higher weight.

IDF(t) = log((N+1)/(df(t)+1)) + 1

The final score is TF × IDF. A word that appears 10 times in one document but appears in every document scores low. A word that appears 3 times in one document but rarely anywhere else scores high.

Use the controls below to explore TF-IDF scores across different corpora and documents.

# TF-IDF with scikit-learn from sklearn.feature_extraction.text import TfidfVectorizer vec = TfidfVectorizer() X = vec.fit_transform(corpus) # Words common across all docs score low (like "the") # Words unique to one doc score high — they're discriminative
Method 4 — One-Hot Encoding
4

One-Hot Encoding

Each word becomes a V-dimensional binary vector — exactly one 1, rest zeros

In one-hot encoding, every word in the vocabulary is represented as a V-dimensional binary vector. The vector is all zeros except at the word's vocabulary index, which is 1. This is the simplest possible word representation — it encodes identity, nothing else.

The critical weakness: every word vector is orthogonal to every other. The cosine similarity between "cat" and "kitten" is exactly 0.0 — identical to the similarity between "cat" and "blockchain". The representation contains zero semantic information.

Select words to see their one-hot vectors. Notice how unrelated words look structurally identical except for the position of the 1.

⚠️ One-hot limitations

  • Dimensionality = V (can be 50,000+)
  • All word vectors are orthogonal — no semantic similarity
  • No notion of "cat" being more similar to "dog" than to "algebra"
  • Cannot generalise to unseen words

✅ Where one-hot is still used

  • Input layer of neural networks before the embedding layer
  • Target labels in multi-class classification
  • Character-level models with small alphabets
  • Categorical feature encoding in traditional ML
Method 5 — Word Embeddings
5

Word Embeddings

Dense low-dimensional vectors where geometric distance encodes semantic meaning

Word embeddings solve the orthogonality problem of one-hot encoding. They map every word to a dense, low-dimensional vector (typically 50–300 dimensions) learned from large text corpora. Words with similar meanings end up geometrically close in this vector space.

The famous Word2Vec insight: "king" − "man" + "woman" ≈ "queen". Semantic relationships become arithmetic in embedding space. This works because co-occurrence patterns in text encode meaning — words that appear in similar contexts carry similar meanings.

Static Embeddings

  • Word2Vec — Skipgram / CBOW, predict context from word
  • GloVe — Global co-occurrence matrix factorisation
  • FastText — Subword-aware, handles OOV words via character n-grams

One vector per word — "bank" always maps to the same vector regardless of context.

Contextual Embeddings

  • ELMo — BiLSTM-based, context-sensitive
  • BERT — Transformer, bidirectional context
  • GPT — Transformer, autoregressive

"bank" gets different vectors in "river bank" vs "investment bank" — context changes the representation.

# Static embeddings with Gensim (Word2Vec) from gensim.models import Word2Vec sentences = [["the", "cat", "sat"], ["the", "dog", "ran"]] model = Word2Vec(sentences, vector_size=100, window=5, min_count=1) model.wv.most_similar("cat") # → [("dog", 0.92), ("kitten", 0.88), ...] # Contextual embeddings with HuggingFace (BERT) from transformers import AutoModel, AutoTokenizer tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased") model = AutoModel.from_pretrained("bert-base-uncased") # Each token gets a 768-dim context-aware vector
Interactive — Cosine Similarity Explorer

Measuring document similarity using feature vectors

Once documents have numeric representations, we can measure how similar they are using cosine similarity — the cosine of the angle between two vectors. A score of 1.0 means identical, 0.0 means completely different.

Cosine similarity is preferred over Euclidean distance because it is length-normalised — a short document and a long document on the same topic score high, whereas their Euclidean distance would be large.
